## Absolute Rules

1. **No passwords.** The User model has no password field. Authentication is
   100% passwordless via emailed one-time codes. Do not add a password field
   under any circumstances.

2. **No out-of-the-box auth libraries** that impose their own schema (NextAuth,
   Clerk, Auth0). Implement the auth flow manually per the spec below.

3. **Prisma is the only way to touch the database.** No raw SQL except in
   migrations generated by Prisma. No other query builders.

4. **All business logic lives in the service layer**, not in API route handlers.
   Handlers: validate input with Zod, call services, return responses.
   Services: call Prisma, enforce business rules, throw typed errors.

5. **RBAC is always enforced server-side.** Middleware checks role on every
   protected route. Client-side role checks are UI convenience only.

6. **Access tokens go in memory only.** Never write localStorage.setItem or
   sessionStorage.setItem for tokens anywhere in the codebase.

7. **Refresh tokens travel via httpOnly cookie only.** Every Set-Cookie for
   refresh tokens must include Secure; SameSite=Strict; HttpOnly; Path=/.

8. **taxId must be encrypted at rest.** AES-256-CBC via Node crypto before
   every write. Decrypt on read for admin-role requests only.

9. **Invoice line items are locked** when the parent Invoice status is Sent,
   Paid, Overdue, or Cancelled. Enforce in the service layer before any
   write — do not rely on the UI disabling buttons.

10. **Task nesting max depth is 1.** A task with a parentTaskId cannot itself
    be a parent. Enforce in the service layer.

11. **Validate all input with Zod.** Every API route must define and parse a Zod
    schema before touching any service. Return 422 with field-level errors on
    failure. Never trust client input.

12. **Never SELECT *.** All Prisma queries must use select or include to
    request only the fields required by the response. This protects sensitive
    fields (codeHash, taxId, deletedAt) from accidental exposure.

## Authentication — Passwordless Email Code

### Flow

1. POST /api/auth/request-code
   - Reject if User.deletedAt is not null
   - Generate: crypto.randomInt(100000, 999999).toString()
   - Hash: bcrypt.hash(code, 10)
   - Invalidate prior active codes: set usedAt = now for this userId
   - Store new AuthCode with expiresAt = now + 15 minutes
   - Send plain code via email (never log the plain code)
   - Rate limit: 5 requests per email per 10 minutes

2. POST /api/auth/verify-code
   - Find active AuthCode: usedAt IS NULL AND expiresAt > now
   - Check attempts < 5
   - Compare: bcrypt.compare(submitted, codeHash)
   - Mismatch: attempts++. If attempts >= 5, set usedAt = now (burn the code)
   - Match: set usedAt = now, update User.lastLoginAt, write audit log
   - Issue JWT: { sub: userId, role }, HS256, TTL 15 min
   - Issue refresh token: crypto.randomBytes(32).toString('hex')
   - Store refresh token HASH in DB with 7-day expiry
   - Set cookie: httpOnly; Secure; SameSite=Strict; Path=/; Max-Age=604800

3. POST /api/auth/refresh
   - Hash the cookie value, look up in DB
   - Must not be expired or revoked
   - Rotate: delete old record, create new token, set new cookie
   - Reuse of revoked token: delete ALL refresh tokens for that userId immediately

4. DELETE /api/auth/logout
   - Hash cookie, delete DB record
   - Clear cookie with Max-Age=0

### JWT Middleware

```typescript
export async function withAuth(req, res, next) {
  const header = req.headers.authorization;
  if (!header?.startsWith('Bearer ')) return res.status(401).json({ error: 'Unauthorized' });
  try {
    const payload = jwt.verify(header.slice(7), process.env.JWT_SECRET) as JwtPayload;
    req.user = { userId: payload.sub, role: payload.role };
    next();
  } catch {
    return res.status(401).json({ error: 'Token expired or invalid' });
  }
}
```

### RBAC Middleware

```typescript
export function requireRole(...roles: Role[]) {
  return (req, res, next) => {
    if (!req.user || !roles.includes(req.user.role)) {
      return res.status(403).json({ error: 'Forbidden' });
    }
    next();
  };
}
```

## Privacy

### taxId — Encryption at Rest

```typescript
// src/lib/crypto.ts
import { createCipheriv, createDecipheriv, randomBytes } from 'crypto';

const ALGORITHM = 'aes-256-cbc';
const KEY = Buffer.from(process.env.TAX_ID_ENCRYPTION_KEY!, 'hex');

export function encryptTaxId(plain: string): string {
  const iv = randomBytes(16);
  const cipher = createCipheriv(ALGORITHM, KEY, iv);
  const enc = Buffer.concat([cipher.update(plain, 'utf8'), cipher.final()]);
  return `${iv.toString('hex')}:${enc.toString('hex')}`;
}

export function decryptTaxId(stored: string): string {
  const [ivHex, encHex] = stored.split(':');
  const decipher = createDecipheriv(ALGORITHM, KEY, Buffer.from(ivHex, 'hex'));
  return Buffer.concat([decipher.update(Buffer.from(encHex, 'hex')), decipher.final()]).toString('utf8');
}

export function maskTaxId(stored: string): string {
  const plain = decryptTaxId(stored);
  return `***-**-${plain.slice(-4)}`;
}
```

Always encrypt before writing. Never store a plain taxId value.
Audit log every admin access to a decrypted taxId.

### PII in Logs

Never log:
- Raw email addresses — log SHA-256 hash prefix instead:
  crypto.createHash('sha256').update(email).digest('hex').slice(0, 12)
- Plain OTP codes
- Raw taxId values
- JWT or refresh token values

### Data Minimisation

Every Prisma query must use select or include — never findMany() with no
select. This prevents accidental exposure of codeHash, taxId, and deletedAt.

### Soft Delete Privacy

Soft-deleted users (deletedAt is not null):
- Return 404 on any lookup — do not reveal the account exists
- Excluded from all list queries: where: { deletedAt: null }
- Cannot request or verify auth codes
- Hidden from admin lists by default (add showDeleted=true param to reveal)

### Invoice Immutability

Once an invoice reaches Sent status it is a financial record:
- No field edits permitted
- No line item changes permitted
- Hard delete blocked — only Cancelled status allowed
- Enforce in the service layer, not just the UI

### N+1 Prevention

Never load a list and then loop to fetch related data. Use include or nested
select to load everything in one query:

```typescript
// Bad — N+1
const projects = await prisma.project.findMany();
for (const p of projects) {
  p.client = await prisma.client.findUnique({ where: { id: p.clientId } });
}

// Good — single query
const projects = await prisma.project.findMany({
  select: {
    id: true, name: true, status: true, dueDate: true,
    client: { select: { id: true, firstName: true, lastName: true } },
    _count: { select: { tasks: true } },
  },
});
```

### Pagination — Cursor-Based on All List Endpoints

All list endpoints must be paginated. Use cursor-based (not offset) pagination:

```typescript
const items = await prisma.project.findMany({
  take: limit + 1,
  ...(cursor ? { skip: 1, cursor: { id: cursor } } : {}),
  orderBy: { createdAt: 'desc' },
  where: filters,
  select: projectListSelect,
});

const hasMore   = items.length > limit;
const data      = hasMore ? items.slice(0, -1) : items;
const nextCursor = hasMore ? data[data.length - 1].id : null;

return { data, meta: { nextCursor, hasMore } };
```

Default limit = 20, max = 100. Never return unbounded lists.

### Prisma Transactions for Multi-Step Writes

Any write that touches multiple records must use a Prisma transaction:

```typescript
async function createLineItem(invoiceId: string, data: CreateLineItemDto) {
  return prisma.$transaction(async (tx) => {
    const invoice = await tx.invoice.findUniqueOrThrow({
      where: { id: invoiceId },
      select: { status: true },
    });
    if (LOCKED_STATUSES.includes(invoice.status)) {
      throw new AppError(409, 'Invoice is locked');
    }
    const lineItem = await tx.invoiceLineItem.create({
      data: { invoiceId, ...data, lineTotal: data.quantity * data.unitPrice },
    });
    await recomputeInvoiceTotals(invoiceId, tx);
    return lineItem;
  });
}
```

Always pass the transaction client tx through to sub-functions so they
participate in the same transaction.

### Invoice Total Recomputation

```typescript
async function recomputeInvoiceTotals(
  invoiceId: string,
  tx: Prisma.TransactionClient = prisma
) {
  const items   = await tx.invoiceLineItem.findMany({ where: { invoiceId }, select: { lineTotal: true } });
  const invoice = await tx.invoice.findUniqueOrThrow({ where: { id: invoiceId }, select: { taxRate: true } });

  const subtotal  = items.reduce((sum, i) => sum + Number(i.lineTotal), 0);
  const taxAmount = Number((subtotal * Number(invoice.taxRate)).toFixed(2));
  const total     = Number((subtotal + taxAmount).toFixed(2));

  await tx.invoice.update({ where: { id: invoiceId }, data: { subtotal, taxAmount, total } });
}
```

Call inside a transaction after every line item create, update, or delete.

## API Response Conventions

- All responses: Content-Type: application/json
- Success: { data: <payload> } with appropriate 2xx
- Error:   { error: "<message>", fields?: <zod errors> } — no stack traces in prod
- Lists:   { data: [], meta: { nextCursor, hasMore } }
- Soft-deleted users always return 404, never 403

### HTTP Status Codes

| Situation | Code |
|---|---|
| Success | 200 |
| Created | 201 |
| Deleted | 204 |
| Validation error | 422 |
| Auth required | 401 |
| Forbidden | 403 |
| Not found / soft-deleted | 404 |
| Conflict / locked | 409 |
| Rate limited | 429 |
| Server error | 500 |
